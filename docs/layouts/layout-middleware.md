# Layout generation API and middleware

Implementation: src/Lib/Plugin/Layout.php, src/Middleware/PageLayout.php, src/Providers/AppServiceProvider.php, src/Lib/Plugin/UpdatePlugin.php.

## Public API

| Signature on Opoink\Oliv\Lib\Plugin\Layout | Result and side effects |
| --- | --- |
| createLayoutByPageName(?string $pageName): void | Validates route name; reads enabled definitions; writes/deletes owned page as applicable |
| createPageComponent(string $pageName, string $targetDir, string $fileName, string $ext): void | Reads that page's declarations and writes the specified target |
| compileLayouts(): void | Discovers immediate resources/layout/*.json files; generates pages and removes obsolete owned targets |
| mergeLayouts(array ...$layouts): array | Returns merged recursive tree; logs invalid contributions |
| toVueComponent(array $layout): string | Renders a normalized merged tree as Vue source; logs invalid attributes |

createLayoutByPageName accepts names matching letters/digits/underscore first, then letters/digits/underscore/dot/hyphen. Null/empty names do nothing; other invalid names warn. The lower-level createPageComponent does not apply that entry-point name validation; pass trusted paths/names.

mergeLayouts returns a list of nodes with name, component, export, attr, and children. Removal state is stripped after resolution. toVueComponent expects this normalized result, not arbitrary raw declaration JSON.

~~~php
$layout = app(\Opoink\Oliv\Lib\Plugin\Layout::class);
$merged = $layout->mergeLayouts($baseDefinitions, $pluginDefinitions);
$vueSource = $layout->toVueComponent($merged);
~~~

See [declaration semantics](page-layout.md).

## Compile-time flow

[oliv:plugins-update](../cli/plugins-update.md) calls compileLayouts before writing frontend import artifacts. Generated pages must exist before [Vite](../frontend/vite.md) evaluates import.meta.glob.

The target directory is storage/framework/vue/pages. Writes are skipped when content is identical. Generated files begin with:

~~~html
<!-- Generated by OLIV Layout; edit plugin resources/layout files. -->
~~~

Cleanup deletes only files beginning with that marker. Unmarked old files and hand-written pages are not deleted, although a declared page with the same target filename can still be overwritten during generation. Filesystem writes use [Writer](../helpers/helper-functions.md), not atomic replacement.

## Request middleware

PageLayout::handle(Request $request, Closure $next): Response calls createLayoutByPageName($request->route()?->getName()) before $next($request).

**Registration status:** the provider's web-group PageLayout line is commented out. The middleware does not run automatically merely because its class exists. A host may register it explicitly. The active supplied generation path is the compiler.

The [render helper](../helpers/inertia-render.md) independently checks for an existing route-derived file and selects it, even when the controller names another page. It does not generate the file itself.

No definitions means no newly created page; all malformed source files preserve the last generated content. Production source changes require regeneration and rebuilding, not just request-time writing.
